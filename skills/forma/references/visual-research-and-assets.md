# Visual research and asset sourcing

Use visual references to understand structure, hierarchy, interaction patterns, and tone—not as material to reproduce. Keep reference links and asset sourcing separate: a gallery listing or an image returned by an API does not by itself establish a right to reuse the image or design.

### Core boundary

Awwwards, Mobbin, Dribbble, Behance, SiteInspire, Godly, and One Page Love are **link-out visual references**, not image-download endpoints for Forma. Do not scrape or download their gallery, portfolio, screenshot, or featured-site images absent explicit applicable permission from the relevant rights holder. Credit and a public URL do not substitute for permission. Where a service offers an API or MCP, use it only within its access terms; programmatic access does not grant underlying media rights.

Unsplash, Pexels, and Wikimedia Commons are asset sources with distinct, conditional terms—not interchangeable blanket licenses. Check the current official license and relevant asset details before production use. This guide summarizes the official pages reviewed, not legal advice or a guarantee that any particular use is covered.

## Practical Forma workflow

1. **Match the reference to the user's site.** Identify the site's audience, task, existing design language, and constraints first. Browse galleries for comparable page types and interaction patterns, not to duplicate a particular composition. Save the canonical reference URL, creator/site name, and a short note describing the pattern to study. Keep any captured reference notes internal and linked rather than embedding gallery media in production.
2. **Choose images for a defined purpose.** Specify the image's role, subject, aspect ratio, crop, and desired mood before searching licensed asset sources. Prefer assets whose source and license can be verified. Check the particular image's current license conditions, required attribution, restrictions, and whether modifications are allowed; do not infer permission from a search result or API response.
3. **Stage assets with provenance.** Before an asset enters a proposed build, record its source page and direct source URL, creator, retrieval date, license/terms URL, applicable attribution text, required changes or restrictions, and intended placement. Use official API routes only where access is authorized and observe their authentication, hotlinking, event, rate, and other requirements. For Commons, preserve file-level license and attribution details. Do not stage gallery/portfolio imagery as reusable assets without permission.
4. **Preview before changing a live site.** Assemble proposed assets and design changes in a preview or staging view. Show the user the preview and the relevant asset/source notes, then obtain approval before any live-site modification. If approval or rights are unclear, leave the live site unchanged and replace or omit the uncertain asset.

## Visual Scout CLI

Forma includes [`visual-scout.mjs`](../scripts/visual-scout.mjs), a comment-free Node.js utility for repeatable inspection. Run it from the target project directory so reports and staged assets stay with that project; replace `<forma-skill>` below with the directory containing this skill's `SKILL.md`.

```bash
node <forma-skill>/scripts/visual-scout.mjs sources
node <forma-skill>/scripts/visual-scout.mjs audit https://your-public-site.example --out .forma-review/site
node <forma-skill>/scripts/visual-scout.mjs image-audit .forma-review/assets/selected/asset.jpg --site-report .forma-review/site/visual-scout-report.json
node <forma-skill>/scripts/visual-scout.mjs pixelize .forma-review/assets/selected/asset.jpg --mode duotone --cell-size 12 --out .forma-review/pixel-art
node <forma-skill>/scripts/visual-scout.mjs assets search "editorial botanical skincare" --limit 8
node <forma-skill>/scripts/visual-scout.mjs assets stage --results .forma-review/assets/commons-flowers-candidates.json --id 12345 --license-checked --confirm
```

The site audit uses a fresh, unauthenticated Playwright session at desktop and mobile widths. It records first-viewport screenshots, page hierarchy, common rendered colors/fonts, image alternatives, control names, form labels, overflow, console errors, and failed requests. The image audit samples dimensions, orientation, transparency, luminance, saturation, and dominant color bins; transparent pixels are preview-composited on white. With a site report, it also includes that page's palette signals for human comparison.

### Original pixel-glyph treatment

`pixelize` is Forma's own deterministic renderer, not a copy of another skill's implementation. It samples every source pixel into aspect-aware cells, averages color in linear light, maps tonal values through a Forma glyph ramp, applies a small ordered 4×4 Bayer pattern to soften banding, and uses local luminance gradients to select directional edge glyphs. Its source-color, monochrome, and duotone modes allow the effect to follow a product's actual palette. The same source and parameters produce the same result; there is no random design preset.

Choose the cell size, ramp, contrast, edge threshold, palette, and placement for the site's art direction instead of applying one effect to every page. Use this treatment for a considered decorative image, not tiny type, logos, charts, evidence, or an image whose detail is essential to understanding. Keep the unmodified source and a meaningful accessible equivalent. A visual transformation does not change the source asset's copyright or license obligations.

The command writes a new PNG and a JSON manifest containing source/output hashes, grid dimensions, renderer settings, and algorithm summary. It never overwrites the input or edits site files. Compare the preview with the site's audit palette, inspect it at intended sizes, and only then incorporate it into a preview build.

### One cohesive design pass

1. Audit the target and write a site-specific design thesis before selecting a visual effect. Use gallery sites to study patterns and interaction ideas; do not transplant their layout, image, or brand treatment.
2. Search for a rights-checkable image whose subject supports the page goal. Preserve its file-level source and license details. Run `image-audit` with the site report to compare palette and aspect-ratio signals.
3. Decide whether glyph rendering strengthens this product's direction. Choose source color, monochrome, or a brand-compatible duotone; tune cell size, glyph ramp, contrast, edge treatment, crop, and placement for the page rather than using one fixed preset.
4. Put the original image and optional glyph treatment into a preview component. Keep essential copy as real text, retain an appropriate text alternative, and provide the unmodified image as a fallback when the effect is unsupported or too small to read.
5. Inspect the result beside the unmodified option at mobile and desktop sizes. Check legibility, contrast, loading behavior, crop, and meaning; adjust the layout and token roles too, not just the image filter. Keep changes in preview until review is complete.

Search returns Wikimedia Commons candidates and a JSON record; it downloads no images. Open each candidate's original file page and verify creator, exact license, modifications, attribution, and project compatibility. Only then use `assets stage` with both `--license-checked` and `--confirm`. It saves the chosen image and attribution/manifest in a review folder, never directly into production code. A human must judge image meaning, crop, accessibility, and fit; measured palette similarity does not make that decision.

The scanner is a heuristic, not an accessibility conformance test or design verdict. It blocks local/private target hosts and requires Playwright/Chromium for visual commands. Do not use it to probe authenticated or unauthorized pages.

## Source freshness

Policies, plan availability, endpoints, and limits can change. Recheck the linked official page at the time of use. A page that redirects, is blocked, dynamically rendered, or lacks visible terms is not evidence of permission or of a current API entitlement. In this research, Awwwards' API route redirected without public API documentation; Behance's present API availability was unclear; Pexels reported that new API keys were paused; and the full Unsplash license/terms text was not readable in the reviewed extraction. Treat these as unresolved or time-sensitive and verify directly before relying on them.
